## 2. Device checks

Moved verbatim from `add-native-auth-handoff` (its section 12) on 2026-11-17. Decision: the first native app runs these checks; read `expo-auth-test/` below as that app, and its "never committed" rule no longer applies.

Throwaway, never committed. Drive on the iOS Simulator, an iPhone for the https return, and an Android emulator; the user starts the adb server (sandbox). grnyte is reached through the reserved ngrok static domain fronting a BUILT `vite preview` over https with `PUBLIC_ORIGIN` set to that origin and `IOS_APP_ASSOCIATION_ENABLED=true` (without it the Apple file 404s and the iOS https return fails with `Code=1`, which is a config gap, not a platform limit), never `npm run dev`; GoTrue is the second local stack's Kong on the host (`localhost` from the Simulator, `10.0.2.2` from the emulator). The app holds only the publishable key (`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`), since every `EXPO_PUBLIC_*` value is inlined into the bundle. Nothing under `expo-auth-test/` gets prettier, eslint or a test. These tasks are the only proof of the `auth/native-sign-in` requirements marked "client contract, not server-verifiable".

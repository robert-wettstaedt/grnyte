# Tasks

Branch and files: design D9. "From the branch" means `git checkout feature/powersync -- <path>` on `feature/engine-seam`. "Develop's" means the file as on `develop`, untouched. A twin is named by inserting `.powersync` before the last extension the import keeps (`resources.powersync.svelte.ts` beside `resources.svelte.ts`, design D1); PowerSync code and tests import twins by that explicit path. Every new test is seen red once (one production edit that breaks it, run, revert).

Tests run red before green, only at these seams (agreed with the user, 2026-11-16), one test and one implementation per cycle:

- E1 the engine plugin in `vite.config.ts`, through its `resolveId`: an unknown engine throws naming the allowed values; `zero` refuses `@powersync/*`, `$lib/powersync/*` and any `*.powersync.*` file; `zero` also refuses `@tanstack/*db*`; `powersync` resolves `./resources.svelte` to `./resources.powersync.svelte`, `./engine` to `./engine.powersync` and an aliased `$lib/entities/area/resources.svelte` to its twin when the twin exists, to the original otherwise; an import from PowerSync code (under `src/lib/powersync/`, a twin, or their tests) is not redirected; both plugins act under `vite build` and `vite dev` and are inactive under vitest.
- E2 the twin contract: `twins.test.ts` fails when a `*.powersync.*` file on disk, tests excluded, has no entry in `twins.ts` (the type check itself is svelte-check). A twin's test is named after the twin (`exploreData.powersync.svelte.test.ts`) and mocks twins by their explicit paths.
- E3 the PowerSync precache: `sw.size.test.ts` over the built service worker asserts the wa-sqlite wasm is precached whenever the build emitted it (`build/client/_app/immutable/workers/assets/`). A Zero build cannot precache it: the guard stops every PowerSync module and the Zero globs exclude `.wasm` (design D6).
- E4 Zero's start-up: `initZero` with the preload off starts no guidebook query and calls neither `trackSyncFor` nor the store probe (Zero's lost-store reload still clears the sync stamps, as on the branch); with the default it starts exactly `develop`'s.
- Carried over from the milestone, unchanged: S4 PowerSync start, clear and status with `@powersync/web` faked; S5 the status bar verdict; S6 a resource's `phase` and `data` (the branch's "a PowerSync resource over faked TanStack collections" cases, moved out of `zero/resource.svelte.test.ts` into `src/lib/powersync/resource.svelte.test.ts`, importing twins by explicit path); S7 engine parity at the mapper; S8 raw SQL under `EXPLAIN QUERY PLAN`; the stream tests: `streams.server.test.ts` and `schema.server.test.ts` need only Postgres and run in CI, `streams.local.server.test.ts` needs the service and skips without it.
- Not unit-tested on purpose: the Zero wrappers of task 5.5 (each calls one existing Zero query; a test would compare query internals), screens and the health page's look. The written comparison with `develop`'s call site, the Zero e2e and the drives cover them.

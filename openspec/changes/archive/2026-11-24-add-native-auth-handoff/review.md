# Plan review: add-native-auth-handoff

Status: stale

Closed after round 3 by the user's decision at the cap; round-3 findings applied without a further round.

## Round 1

- Snapshot: frozen copy at `add-native-auth-handoff-r1` (the worktree guard refuses the temp-index commit recipe); code at develop `7e25d347`. Prerequisite changes (read from `openspec/changes/`): `migrate-supabase-keys`, `harden-auth-codes`, `add-social-sign-in`.

- Reader paraphrase, what this proposes: "The change gives the coming Expo app every server-owned auth step as Bearer-only JSON endpoints under `/api/app/v1/`, each running the same handler body as its web remote function. Google (both platforms) and Apple on Android sign in through a browser handoff: the app registers a PKCE challenge, the provider returns to the web's own `/auth/callback/<provider>`, a new \"app carrier\" claims the flow from a server table by `hash(state)`, and the browser is sent to `rocks.grnyte:/auth?code=` with a 60-second single-use code the app trades for a session. iOS Apple sign-in and \"Confirm with Apple\" run natively with nonces; it also adds universal-link files, a throwaway uncommitted Expo test app, and freezes `/api/app/v1` as a widen-only contract."
- Reader paraphrase, how the existing system works per this plan: "The hook sequence builds a cookie-based `locals.supabase` and verifies the cookie token with `verifyAccessToken` (jose); nothing reads `Authorization` except the Zero endpoints through `zeroCaller`. Change 1 (`harden-auth-codes`) adds `APP_API_PREFIX` (cookie-blind in `authGuard`, exempt from `crossSiteGuard`), code-based auth bodies, re-auth grants, session liveness and the auth event log; change 2 (`add-social-sign-in`) adds an own OAuth client with a list of transaction carriers, `completeOAuth`, `dispatchIntent`, sealing, and Apple secret/revoke/confirm helpers. Auth steps are remote functions; Kit's CSRF check and `vercel.json` decide today's cross-origin behaviour."

## Round 2

- Reader paraphrase, what this proposes: "The change gives the coming Expo app every server-owned auth step as Bearer-only JSON endpoints under `/api/app/v1/`, each running the same handler body as its web remote function behind its own widen-only request and response shapes. Google on both platforms and Apple on Android sign in through a browser handoff: the app registers an S256 PKCE challenge and its return channel, the provider returns to the web's own `/auth/callback/<provider>`, a new app carrier claims the flow by `hash(state)` from `app_auth_flows`, and redirects to `/app-return` over https on iOS or `rocks.grnyte:/auth` on Android with a 60-second single-use code the app trades for a session. Apple sign-in and \"Confirm with Apple\" run natively on iOS, every device-supplied Apple ID token is verified against Apple's keys first, and the change adds link files and a throwaway Expo test app."

Change 1 adds `APP_API_PREFIX` (exempt from `crossSiteGuard`, cookie-blind in `authGuard`), code-based auth bodies, re-auth grants, session liveness and the auth event log; change 2 adds its own OAuth client: an ordered `carriers` list (`take`/`land`), `completeOAuth` behind `/auth/callback/<provider>`, `dispatchIntent(DispatchContext, tx, proof)`, `seal`, and the Apple secret, revoke and confirm helpers.

## Paraphrases

### Round 1 (reader)

**What this proposes.** Issue 1183 closes R1. The PowerSync build stops calling `initZero` in `engine.powersync.ts`, so it opens no socket to zero-cache and keeps working with zero-cache down. The Zero client guard drops its allow-list (`ZERO_CLIENT_IMPORTERS`) and refuses any import of `z.svelte.ts` or `zero-svelte` in a PowerSync build. `initZero` loses its `preload` option. e2e stops requiring zero-cache for a PowerSync run. Both builds get e2e, drives, a build-output probe and a runtime probe. A fresh reviewer does a security review of the stream predicates, the write route, the server reads and the change markers. The specs, CONTEXT, AGENTS and the roadmap then say a preview may build PowerSync while production stays on Zero.

**How the existing system works, per this plan.** A build-time switch (`PUBLIC_SYNC_ENGINE`) picks Zero or PowerSync. The PowerSync build swaps modules for their `*.powersync.*` twins and reads the guidebook from PowerSync. It sends writes to `/api/sync/mutate`, which runs the server mutators on the app server. It fetches the feed, inbox and comments as `readQuery` server reads that refresh when their change markers move. It still starts a Zero client with `preload: false` that nothing reads, and a Vite guard refuses that client to every module except `engine.powersync.ts`. Production builds Zero, and e2e always requires zero-cache.

Both match the intent of issue 1183.

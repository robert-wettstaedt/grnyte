# Tasks

Work in the worktree, plus the branch's own stack under `<second stack>/`. Never
edit the shared stack (`<shared stack>`), never migrate the shared DB, never read the
repo `.env` (the sandbox denies it; `<second stack>/.env` is the branch stack's own and is read freely).
Dashboard, Bitwarden, Vercel and VPS steps (group 7) are run by the user, in the order of design.md
Migration Plan. Each code task names its merge: A (deployment, released first), B (app), C
(PowerSync without the secret, at step 4b), plus the switch `keys/z-zero-jwks` (Zero's key swap, dispatched at step 4);
every verify passes in the tree of its own merge. Each
merge ships from its own `keys/*` branch as a normal develop to main release (7.0, 7.0c). "Seen red" means: make the named production
edit, grep that it applied, run the test, watch it fail, revert.

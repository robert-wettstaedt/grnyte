"Seen red" means: make the named production edit, run the test, watch it fail, revert, and grep that the edit actually applied. "(create)" and "(modify)" mark each file a task touches.

GoTrue in tests. CI has no GoTrue. A line marked "GoTrue:" is an assertion against the second local stack's GoTrue; it lives in its own `describe.skipIf` block keyed on the stack's env (as `harden-auth-codes` does), runs by hand before review, and never decides CI. Whether GoTrue accepts a fake-issuer token is that change's spike (its 5.0): if it does not, server tests mock `signInWithIdToken` and `linkIdentity` at change 2's `DispatchContext` seam (`authServer`, `supabaseAuthServerAs`) and prove change 1's identity trigger by direct identity inserts as change 1's own tests do; GoTrue's acceptance of the bundle ID is left to one real native token on a device (12.8).

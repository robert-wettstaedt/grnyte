# Tasks

Follows the resolved rulings R1 to R10 in proposal.md.

Test-driven, at seven agreed seams only (user, 2026-11-16; S5's `signInMethodsQuery` and S7 added at review P66):

- **S1** `POST /api/webhooks/apple/sign-in`, driven with JWS fixtures signed by a test key swapped in through `appleKeys.source`; outcomes observed only through S2 to S6 and the auth event log (an output the spec defines).
- **S2** `guard_auth_identity`, through SQL deletes on `auth.identities` (`src/lib/db/authGuards.server.test.ts`).
- **S3** `sendEmailOutcome`, with Resend stubbed at the network edge as today.
- **S4** the re-authentication command in `src/lib/auth/reauthSteps.server.ts`.
- **S5** the `identities.remote.ts` remotes: `unlinkProvider`, `mailForwardingQuery`, and `signInMethodsQuery` to observe linked providers; a remote refusing as signed out is how a test observes that a session ended (`src/lib/auth/identities.remote.test.ts`).
- **S6** the `/settings/email` page and `ReauthStep.svelte` (browser project).
- **S7** the native "Confirm with Apple" endpoint `POST /api/app/v1/reauth/apple/confirm`, through the existing `appCall` fixture with an Apple ID token signed by the test key and Apple's revoke endpoint stubbed at `providerHttp`.

No test targets an internal (`verifyAppleJwt`'s classification, the `events` parser, `notForwarding`, `recentAppleEvent`, `signInMethods`): each is reached through a seam. The existing `verifyAppleIdToken` tests stay as they are; they guard the native app. What only real Apple can show (a later Apple sign-in landing in the same account, GoTrue's own mails) is checked in task 8.2, not in tests.

Each slice below is one cycle: write the test for that behaviour at its seam, see it fail for the stated reason, write only the code that makes it pass, then the next slice. Every slice names its red reason; no slice writes code a later slice's test asks for. Removals (group 3) change no behaviour; the only test they edit is named in the task.

Every S1 and S2 test runs against the throwaway database from 1.2 (and the branch's local GoTrue stack for GoTrue paths), never the shared dev database.

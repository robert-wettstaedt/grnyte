### Round 1 paraphrases (reader)

**What this proposes.** In the PowerSync build, the online flag and status bar stop reading the leftover Zero client and read PowerSync. They do so through three new engine-seam functions (`connection`, `storeBlocked`, `recoverSignIn`). Zero's sign-in recovery becomes Zero-only. In its place, a write answered 401 does one real token refresh and signs the device out locally if the refresh is definitively refused; a server read refused with `auth_sessionEnded` leaves too. A tab still opening its database after 3 s, while another client holds the lock, shows "Open in another tab". An account switch holds the layout load until the reload and suppresses both redirects. The 3 s reload wait and the `derived_inert` warnings are traced, with stop lines.

**How the existing system works, per this plan.** `initZero` runs in both builds and feeds `online.svelte.ts`. The status bar, global state and app layout read Zero's connection state, and the layout runs the recovery. The PowerSync build passes `preload: false` but still reports Zero's connection. On Safari, iOS and Android, PowerSync takes a per-operation navigator lock `db-lock-<file>` in a dedicated worker. auth-js keeps an unexpired token after its refresh is refused, so a 401 is resent with the same token. On a switch, `leaveForOtherAccount` clears the database (3 s cap) and reloads. Meanwhile the load delivers the new session, queries rebuild on an unset database, and that throws.
